## 1. 目标与范围

让项目成员能够导入、编辑、发布 Skill，并让 Agent 和 Team 使用可追溯的确定版本。草稿修改和新版发布不得改变已接收运行的内容；权限撤销必须在后续执行边界生效。

## 3. 方案比较与推荐

1. 本地目录增加版本子目录：改动较小，但多实例、事务、项目隔离仍需额外机制，适合作为临时单机方案。
2. PostgreSQL 管理资源和版本，MinIO 保存不可变文件包：复用现有基础设施，事务与权限模型可与 Team 对齐；推荐。
3. 外置 Git/制品仓库作为发布源：适合已有技能供应链的团队，但增加仓库权限、同步及发布协调，留待后续集成。

采用方案 2。保持 FastAPI、SQLAlchemy/Alembic、PostgreSQL、MinIO，以及 Vue 3、TypeScript、Ant Design Vue。小型 Skill 包沿用现有限额，首期不增加新的任务队列或独立微服务。

## 4. 资源、版本和发布

- Skill 资源使用 UUID；名称只在 `(unit_id, project_id)` 内唯一。所有读取和变更都显式传入作用域。
- `skills` 保存归属、名称、描述、启用状态、当前发布版本及审计时间。
- `skill_drafts` 保存可编辑正文、文件清单、草稿 revision；保存和发布必须携带预期 revision，陈旧更新返回 409。
- `skill_versions` 保存服务端递增版本号、清单中的展示版本、正文、文件包摘要、不可变对象引用、发布人和发布时间。展示版本不作为唯一标识。
- 文件清单记录规范化相对路径、大小和 SHA-256；对象路径由服务端生成，不接受调用者传入任意存储路径。
- 发布先验证全部文件和对象可读取，再在数据库事务中锁定资源、确认 revision、插入版本并切换指针，同时追加审计。事务失败只留下不可见的待清理对象。
- 发布支持幂等键；同键同请求返回同一结果，同键不同请求拒绝。对象清理只能处理数据库确认未发布、未引用的对象。
- 导入只生成草稿。同名可跳过、改名或更新草稿，不能覆盖历史发布版本。多 Skill ZIP 先完整校验，再原子提交本批草稿，避免半成功未报告。
- 已发布内容不可改写。回退通过把历史内容复制到草稿后发布新版完成。
- 首版只允许删除未发布且无引用的草稿资源；已发布资源可停用并保留历史，不自动物理删除。

## 5. 权限与界面范围

推荐首版以项目为边界，沿用现有 `skill.read`、`skill.manage`、`skill.invoke`，分别用于读取、草稿及发布管理、运行时使用。

角色调整必须明确落入迁移及测试：建议 project_admin 获得本项目 skill.manage；单位管理员在其单位内选定项目操作；其他角色维持现有权限。发布暂由 skill.manage 控制，不引入未设计完整的双人审批。

不能根据前端 project_id 或旧版 role 字符串直接授权。复用服务端授权上下文与资源目标校验；无身份返回 401，无操作权限返回 403，跨作用域资源详情统一为 404。列表、导入、导出、版本读取和引用查询均受相同范围约束。

Skill 的工具声明和正文不能授予工具权限。实际工具访问仍需通过 Gateway，并取调用者权限、Agent/Team 已绑定能力与当前可用能力的交集。

## 6. Agent / Team / Run 的一致性

新增绑定采用 `(skill_id, skill_version_id)`，用户显式选择已发布且启用的版本。新版 Skill 发布后，仅提示可升级；现有绑定不会自动跟随最新版。

Agent 运行接收时校验绑定并持久化版本标识、摘要和有界正文，后续快照构建不得重新解析当前名称或最新版本。Team 发布时固定相同引用；Run 接收时固定 Team 发布版本并校验其 Skill 引用。

单 Agent 与 Team 统一向工厂传递正文和版本元数据。恢复运行必须读取原有快照，摘要不一致、版本缺失或无法授权时返回明确错误，不回退到本地同名目录。

普通草稿修改、新版发布不会影响已接收运行。紧急停用或权限撤销会阻止新运行，并在后续模型、工具及恢复边界阻止继续使用相关 Skill。已发送到模型或已经执行的外部操作不能撤回，需在审计中准确体现边界。

Skill 正文总量应同时受现有快照字节上限和模型上下文预算约束；超限在接受运行前给出可定位的错误，不能静默丢弃某个 Skill。具体默认预算在实施计划中结合现有模型限制确定。

## 7. ZIP 附件及执行边界

沿用 10 MiB 压缩包、20 MiB 解压后、500 个条目的上限，增加流式实际字节计数、重复规范化路径、大小写冲突、特殊文件及嵌套 Skill 根目录的校验。

首批交付把完整包版本化保存，并支持授权后的文件清单和正文查看。运行时保证 `SKILL.md` 正文生效。发布页明确显示附件运行支持状态；文件已保存不能显示为脚本已可执行。

下一批提供受限的文本参考文件读取：请求只能使用快照内的 Skill 版本和清单路径，经过 Gateway 校验作用域、摘要、停用状态及大小后返回有界内容。不得把 MinIO 凭据或宿主目录交给 Agent。

脚本自动执行和依赖安装不在这两批交付内；需要先约定输入输出 Schema、风险级别、工具授权和沙箱执行契约。首批验收只使用正文自包含的 Skill；依赖附件或脚本的旧技能必须标记待适配。

## 8. 旧数据迁移与兼容

先生成只读盘点报告：旧目录清单及摘要、Agent 名称绑定、Team 已发布正文快照、缺失或停用资源及项目归属冲突。不得推测全局旧 Skill 应属于哪个项目。

迁移执行需要显式的单位和项目映射。同一旧 Skill 被多个项目使用时，按映射复制成各项目独立资源，不创建隐式公共访问。

旧目录导入为草稿并保留源文件；迁移使用源摘要和目标作用域作为幂等标识。旧 Agent 绑定须在目标版本经审核发布后再转换。

既有 Team 版本和 Run 快照不可原地改写。切换前单独列出旧格式的在途、待审批和可恢复运行，确定排空或兼容方案；新运行切换到新格式后禁止名称回退。已发布旧 Team 使用原捕获正文生成待审核的迁移草稿，重新发布才能进入新链路。

这些要求是上线门槛：归属未映射或恢复兼容未验证时，不执行数据切换。回滚保留数据库迁移备份、旧目录与对象，不以恢复可变文件读取作为在线降级。

## 9. 界面设计

现有 Skill 管理入口增加项目上下文，列表展示名称、草稿状态、发布版本、启用状态、更新时间及可用操作。搜索和分页改为服务端执行，列表不返回全部正文。

详情采用“概览、草稿、版本、文件、引用、审计”页签。编辑只保存草稿；发布前显示差异、校验结果及附件支持状态；版本页可查看不可变正文并复制到草稿。

Agent 编辑页选择 Skill 和确定版本，展示新版本提示；Team 发布页展示成员实际使用的 Skill 版本。运行审计记录版本 ID、摘要和处理结果，不将全部正文或文件内容写进通用日志。
