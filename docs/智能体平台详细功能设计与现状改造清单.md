# 智能体平台详细功能设计与现状改造清单

## 1. 文档目标

本文基于当前仓库实现和《水利智能体平台建设方案》第 19 章，细化多用户隔离、Agent Harness、Deep Agents、RAG 知识驱动、Skill/MCP 执行、人工审批、外部专业智能体及 GeoLibre/GIS 接入的功能设计，并明确当前代码需要保留、修改、新增和替换的内容。

本文中的“当前已实现”仅表示已有可工作的配置管理能力，不等同于已经具备生产级智能体运行能力。

## 2. 当前项目现状

### 2.1 已实现能力

| 模块 | 当前实现 | 结论 |
| --- | --- | --- |
| Agent 管理 | PostgreSQL 持久化、增删改查、复制、启停、置顶、Web/Desktop/Common 形态、模型绑定、多个 Skill 绑定、Prompt、审批策略字段 | 可保留并扩展 |
| Skill 管理 | 基于 `SKILL.md` 的文件池、增删改查、启停、ZIP 导入、安全解压、标签和来源 | 可保留内容格式，存储与权限模型需改造 |

### 2.2 当前关键缺口

1. 后端 API 没有认证依赖，也没有 `tenant_id`、`project_id`、`user_id` 运行上下文。
2. Agent、MCP 以全局 ID 为主键，Skill 使用全局文件目录，无法实现多租户同名资源和数据隔离。
3. Agent 只完成配置管理，没有调用、流式输出、中断、恢复、取消、检查点和真实运行状态。
4. `approval_policy` 只是配置字段，没有工具风险解析、审批单、参数摘要和恢复执行能力。
5. Agent 当前只能绑定 Skill，不能绑定知识库、MCP 工具、外部智能体及细粒度能力白名单。
6. 每个 Agent 创建固定本地工作目录，不适合多用户并发和临时沙箱；目录中仅生成 `AGENTS.md`。
7. MCP 的 `headers`、`env` 当前位于配置 JSON，缺少独立密钥管理和按任务临时注入。
8. 没有知识入库、解析、切分、索引、混合检索、引用和知识规则审核能力。
9. 没有外部 Agent 注册、A2A、异步任务、回调、成果文件和 GIS 专用元数据。
10. Agent、MCP 和模型供应商已迁移到 PostgreSQL；后续仍需补充租户/项目字段、行级授权和多实例任务协调机制。

## 3. 目标系统边界

```text
前端控制台 / Web Chatbox / 桌面客户端 / 第三方系统
                         ↓
认证网关与后端管理 API
  ├─ 用户、租户、项目、角色与资源授权
  ├─ Agent、Skill、MCP、知识库、外部 Agent 管理
  ├─ 会话、审批、审计和运行记录管理
  └─ 签名上传、成果下载和事件订阅
                         ↓
ai-services/agent-runtime
  ├─ PlatformAgentHarness
  ├─ Deep Agents 适配器
  ├─ Prompt/Skill/Tool/Knowledge Resolver
  ├─ 风险策略与审批中间件
  ├─ Checkpoint、流式事件和任务控制
  └─ Sandbox / External Agent Adapter
                         ↓
模型、向量检索、MCP、Skill、GIS/GeoLibre、水文与控制服务
```

后端管理 API 负责控制面，`ai-services` 负责运行面。两者可在第一阶段同进程部署，但代码和接口边界从一开始分离，避免后续无法独立扩容。

## 4. 身份、租户与项目隔离设计

### 4.1 功能设计

- 支持用户、租户、项目、成员和角色管理。
- 用户登录后由服务端签发短期访问令牌和刷新令牌。
- 每次请求由服务端生成 `RequestContext`，至少包含用户、租户、当前项目、角色和权限集合。
- Agent、Skill、MCP、知识库、外部 Agent、会话、文件和运行记录统一实现资源域：`private`、`project`、`tenant`、`public`。
- 公共资源只允许引用，不允许普通用户修改；复制到个人或项目后形成独立版本。
- 所有查询默认注入租户条件，跨租户访问不能依靠前端隐藏菜单实现。

### 4.2 建议核心模型

```text
users(id, username, password_hash, status)
tenants(id, name, status)
projects(id, tenant_id, name, status)
tenant_members(tenant_id, user_id, role_id)
project_members(project_id, user_id, role_id)
roles(id, tenant_id, name)
permissions(id, code)
role_permissions(role_id, permission_id)
resource_acl(resource_type, resource_id, subject_type, subject_id, action)
```

业务资源统一增加：

```text
tenant_id, project_id, owner_user_id, visibility, created_by, updated_by
```

### 4.3 当前功能修改

- 新增 `backend/app/auth/`、`backend/app/tenants/`、`backend/app/projects/` 和统一 `RequestContext` 依赖。
- 修改 `backend/app/main.py`，为受保护路由挂载认证依赖和统一异常处理。
- 修改 Agent、MCP、Skill、模型供应商的 Service/Store，所有方法显式接收上下文或作用域，禁止无条件全表查询。
- 将 `frontend/src/stores/permission.ts` 的 Mock 登录改为调用 `/api/auth/login`、`/api/auth/refresh`、`/api/auth/me`。
- 将权限判断作为界面便利功能保留，但安全判定全部由后端执行。

## 5. Agent 管理详细设计

### 5.1 Agent 配置

Agent 配置分成五组：

1. 基础信息：名称、标识、描述、图标、运行形态、语言、所有者、可见范围、启停和版本。
2. 模型配置：供应商、模型、温度、最大输出、超时、降级模型和成本限额。
3. 能力绑定：多个 Skill、MCP 工具、知识库、外部 Agent 和业务模型。
4. Prompt 配置：系统 Prompt、Web 页面上下文 Prompt、桌面上下文 Prompt、输出格式和版本。
5. 运行治理：Harness 类型、最大执行步数、任务超时、并发、记忆策略、风险策略、沙箱策略和日志级别。

建议将当前 `AgentConfig` 扩展为显式绑定对象，而不是继续添加名称字符串：

```json
{
  "skill_bindings": [{"skill_id": "...", "version": "1.2.0", "enabled": true}],
  "mcp_bindings": [{"mcp_id": "...", "allowed_tools": ["query_layer"]}],
  "knowledge_bindings": [{"knowledge_base_id": "...", "usage": ["answer", "planning"]}],
  "external_agent_bindings": [{"external_agent_id": "...", "allowed_capabilities": ["gis.map.render"]}]
}
```

### 5.2 Agent 生命周期

状态分为配置状态和运行状态：

- 配置状态：`draft`、`published`、`disabled`、`archived`。
- 运行状态：`queued`、`running`、`waiting_approval`、`succeeded`、`failed`、`cancelled`、`timed_out`。

当前 `startup_status=ready/disabled` 应改名为 `configuration_status`，不能继续用于表达是否存在运行进程。

### 5.3 配置发布

- 编辑保存生成草稿版本，不直接影响正在运行的会话。
- 发布时校验模型、Skill、MCP、知识库和外部 Agent 是否存在、启用且有权访问。
- 发布生成不可变 `agent_version`，每个 Run 固定引用版本。
- 删除操作改为归档；存在运行记录或审计引用的版本不能物理删除。

### 5.4 当前功能修改

- 修改 `backend/app/agents/schemas.py`：增加资源归属、版本、显式能力绑定、运行限制和风险策略；废弃单一 `skill_names` 作为长期接口。
- 修改 `backend/app/agents/store.py`：从 `config_json` 单表演进为 `agents`、`agent_versions`、`agent_skill_bindings`、`agent_mcp_bindings`、`agent_knowledge_bindings`、`agent_external_bindings`。
- 修改 `backend/app/agents/service.py`：校验绑定资源的租户、项目、启停、版本和授权；工作区不再使用全局 `agent_id` 路径。
- 固定工作目录只保存 Agent 配置资产；真正执行时由 Sandbox Manager 创建 `tenant/run` 临时目录。
- 修改 Agent 管理页面，在现有三个页签上扩展为“基础配置、模型与能力、知识与记忆、Prompt、安全与运行、版本记录”。
- 现有多个 Skill 卡片选择器保留，并用同样交互增加知识库、MCP 工具和外部 Agent 多选器。

## 6. PlatformAgentHarness 与 Deep Agents 运行设计

### 6.1 运行接口

```python
class AgentHarness(Protocol):
    async def invoke(self, request: AgentRunRequest) -> AgentRunResult: ...
    async def stream(self, request: AgentRunRequest) -> AsyncIterator[RunEvent]: ...
    async def resume(self, decision: ApprovalDecision) -> AgentRunResult: ...
    async def cancel(self, run_id: str, actor: RuntimeActor) -> None: ...
```

`AgentRunRequest` 包含不可由客户端伪造的运行上下文、Agent 版本、会话、输入消息、页面或桌面上下文、附件引用和幂等键。`RunEvent` 至少支持消息增量、计划步骤、工具开始、工具结果、引用、审批请求、成果文件、错误和完成事件。

### 6.2 运行流程

```text
校验用户与 Agent 权限
→ 固定 Agent 版本并创建 Run
→ 解析模型、Prompt、Skill、MCP、知识和外部 Agent
→ 分配检查点与临时沙箱
→ Deep Agents 推理和工具循环
→ 工具调用前执行策略检查
→ 低风险自动执行 / 高风险创建审批并中断
→ 审批后校验参数摘要并恢复
→ 保存消息、引用、产物、指标与审计
→ 清理沙箱并结束 Run
```

### 6.3 检查点和取消

- `thread_id` 由平台基于租户、会话和 Run 生成不可猜测标识。
- 检查点不能只存在进程内；开发阶段可 SQLite，生产使用 PostgreSQL/Redis 支持的持久化实现。
- 取消操作写入取消标志，运行器在模型调用和工具步骤边界检查；异步外部任务同时调用其取消接口。
- 恢复必须校验审批人权限、Run 当前状态、审批版本和参数摘要。

### 6.4 新增代码

```text
ai-services/
  agent-runtime/
    domain.py
    harness.py
    deep_agents_adapter.py
    agent_factory.py
    runtime_context.py
    prompt_resolver.py
    skill_resolver.py
    tool_resolver.py
    knowledge_resolver.py
    external_agent_resolver.py
    approval_middleware.py
    backend_factory.py
    checkpoint.py
    event_stream.py
```

后端新增 `/api/agent-runs`：

- `POST /api/agent-runs`：创建运行。
- `GET /api/agent-runs/{id}`：读取状态和结果。
- `GET /api/agent-runs/{id}/events`：SSE 流式事件。
- `POST /api/agent-runs/{id}/cancel`：取消。
- `GET /api/agent-runs/{id}/artifacts`：读取成果列表。

## 9. MCP 管理与工具治理设计

### 9.1 功能设计

- MCP 客户端按租户/项目注册，支持连接测试、能力同步、版本差异、健康状态和调用统计。
- 工具元数据增加风险等级、读写类型、幂等性、超时、审批规则、数据域和参数脱敏规则。
- Agent 绑定 MCP 时选择工具白名单，而不是默认获得客户端全部能力。
- HTTP/SSE MCP 由服务连接；stdio MCP 只能由隔离 Worker 启动。
- 密钥存入 Secret Store，数据库仅保存 `secret_ref`。

### 9.2 当前功能修改

- 修改 `McpClientConfig`，将 `headers`/`env` 中的敏感值替换为凭据引用；读取接口永不返回可复用密钥。
- 修改 `McpStore` 的全局 `client_key` 主键，使用内部 UUID，并为 `(tenant_id, project_id, client_key)` 建唯一约束。
- 工具同步结果从 `tools_json` 迁移至 `mcp_tools` 表，支持单工具风险和策略配置。
- 当前白名单逻辑保留为客户端默认白名单，再增加 Agent 绑定级白名单，实际可用集合取二者交集。
- 管理页面增加健康检查、风险标注、凭据选择、调用统计和 Agent 引用关系。

### 9.3 stdio MCP Worker 实现

当前实现边界必须在产品状态和接口文档中明确：

| 能力 | 当前状态 |
| --- | --- |
| stdio 客户端配置登记 | 已实现 |
| `command`、`args`、`env`、`cwd` 校验与持久化 | 已实现 |
| 隔离进程启动与 MCP initialize | 未实现 |
| `tools/list` 与 `tools/call` | 未实现 |
| Agent 运行时工具注入 | 未实现 |

建议按以下执行面组件拆分：

```text
ai-services/
  mcp-runtime/        # McpRuntimeAdapter、协议模型、Worker 客户端
  sandbox-manager/    # 策略、配额、生命周期与清理
worker/
  mcp-sandbox/        # 进程 runner、stdio 会话与子进程树管理
```

`ToolGateway` 负责鉴权、Agent 工具白名单、风险策略、参数校验和结果标准化；`SandboxManager` 负责分配隔离环境、挂载、网络和资源限制；`McpSandboxWorker` 仅在沙箱中启动 stdio 服务并通过 stdin/stdout JSON-RPC 完成初始化、能力发现和调用；`SecretStore` 只向任务注入短期凭据引用；RunStep、RunEvent 和审计日志记录调用摘要、资源消耗、终态和清理结果。

控制面 API 只保存配置、发布版本和请求同步，不得创建子进程。Worker 接收包含租户、项目、Run、客户端发布版本、工具白名单、镜像摘要、输入 Artifact 和 `secret_ref` 的不可变执行包。执行时必须服务端解析已发布配置，不信任浏览器即时提交的 `command`、`env` 或 `cwd`。能力发现结果写入 `mcp_tools`，工具调用结果标准化为 RunStep/RunEvent；文件类结果经对象存储登记为 Artifact 后再返回引用。

沙箱按 Run 或工具调用临时创建，不为用户永久保留。启动前只挂载批准的只读输入和任务目录，并限制 CPU、内存、磁盘、进程数、时长、网络出口及挂载路径；命令、镜像和依赖包使用白名单及不可变摘要。stdout 只传 MCP 协议，stderr 独立采集、限量并脱敏。成功、失败、超时、取消和空闲超时均须终止完整子进程树、上传批准输出、记录清理结果并销毁沙箱。

生产 MVP 首先提供 HTTP/SSE MCP；stdio 配置可登记但状态显示为“等待沙箱 Worker”。stdio 执行能力在 Sandbox Manager 与 Tool Gateway 阶段交付，不允许在 FastAPI 进程中用本地 Shell 临时替代。

验收测试至少包括：在沙箱中完成 `initialize`、`tools/list` 和 `tools/call`；未发布或未授权工具无法调用；取消、超时及异常退出能清理完整子进程树；Worker 无法读取宿主机未授权文件；凭据不进入日志、Prompt、检查点和 Artifact；各终态的输出、审计及清理记录完整可追踪。

## 10. RAG 知识库详细设计

### 10.1 知识库生命周期

```text
创建知识库 → 上传/连接数据源 → 病毒和格式检查
→ 文档解析/OCR → 结构化切分 → 元数据增强
→ 向量与关键词索引 → 抽检 → 发布 → 增量更新/失效
```

支持文件、网页、数据库、对象存储和业务 API 数据源。水利资料至少记录工程、站点、流域、时间范围、文号、版本、生效时间、失效时间、密级和坐标系等元数据。

### 10.2 检索能力

- 向量、关键词和元数据过滤的混合检索。
- 查询改写、权限过滤、去重、重排和最低相关度。
- 返回片段、文档、页码或章节、版本、得分和签名预览地址。
- 检索前必须先应用租户、项目、用户和数据密级过滤，不能检索后再隐藏结果。
- 回答中的每项关键事实可关联引用，用户可打开原文定位。

### 10.3 知识驱动行为

- `answer`：只用于回答依据。
- `planning`：参与方案和任务计划。
- `behavior`：仅允许审核发布的结构化规则参与行为建议。

行为规则包含条件表达式、建议能力、参数模板、约束、风险等级、数据新鲜度、来源版本和有效期。规则命中后只产生候选动作，仍需经过工具 Schema、权限、实时数据和审批校验。

## 11. 风险策略与人工审批设计

### 11.1 策略模型

最终风险结果取以下策略中的最严格值：

```text
平台策略 > 租户策略 > 项目策略 > 用户角色限制
          > Agent 策略 > Tool/Skill/外部 Agent 风险 > 本次参数规则
```

动作支持 `auto_allow`、`require_approval`、`require_dual_approval`、`deny`。生产控制命令不能由 Agent 自身的 `never` 配置降级为自动执行。

### 11.2 审批单

审批单保存 Run、调用能力、目标对象、规范化参数、参数摘要、知识依据、数据版本、风险原因、申请人、审批人、过期时间和决策。参数摘要使用服务端规范化 JSON 计算；恢复前重新计算并比较。

### 11.3 当前功能修改

- 将当前 `never/control_commands/always` 迁移为 Agent 默认偏好，不再作为最终策略。
- 新增 `backend/app/policies/`、`backend/app/approvals/` 和审计事件。
- 前端新增“待我审批”和“审批策略”页面；会话内显示审批卡片，但最终批准调用后端审批 API。
- 控制类动作支持双人复核、职责分离、审批超时和撤销。

建议 API：

- `GET /api/approvals?status=pending&assignee=me`
- `GET /api/approvals/{id}`
- `POST /api/approvals/{id}/approve`
- `POST /api/approvals/{id}/edit-and-approve`
- `POST /api/approvals/{id}/reject`
- `POST /api/approvals/{id}/respond`

## 12. 沙箱管理设计

### 12.1 功能设计

- 按 Run 或工具调用创建临时沙箱，不为每个用户维护永久容器。
- 沙箱模板定义镜像、CPU、内存、磁盘、超时、进程数、网络出口和只读挂载。
- 通过一次性令牌获取输入文件和密钥；输出文件上传对象存储后销毁环境。
- 记录镜像摘要、命令摘要、资源使用、网络目标、退出码和清理结果。
- 默认禁止访问宿主机、Docker Socket、云元数据地址和其他租户网络。

### 12.2 当前功能修改

- 当前固定 Agent 工作区不再承担安全边界。
- 新增 `ai-services/sandbox-manager/` 和独立 Worker；本地开发可提供受限模拟实现。
- 将 `SandboxMonitorView.vue` 从 Mock 表格改为真实任务、资源占用、日志、产物和终止操作。
- stdio MCP 和脚本型 Skill 统一通过 Sandbox Manager，不允许 FastAPI 主进程直接启动不可信命令。

## 13. 外部智能体与 GeoLibre/GIS 设计

### 13.1 外部智能体注册

注册中心支持 `mcp`、`openapi`、`a2a` 和 `async_job` 四类适配器。配置包括服务地址、认证引用、能力清单、输入输出 Schema、同步方式、超时、重试、并发、费用限额、数据域、风险和审批策略。

统一运行状态：`submitted`、`running`、`waiting_input`、`succeeded`、`failed`、`cancelled`。异步任务支持轮询、Webhook 和消息队列回传，并通过平台任务 ID 映射外部任务 ID。

### 13.2 GeoLibre 接入

建议第一阶段先对 GeoLibre 能力做技术勘察，再按实际接口选择：

- 确定性 GIS 能力包装为 MCP 或 OpenAPI 工具。
- 自带规划、上下文和任务状态的 GeoLibre Agent 通过 A2A 接入。
- 长时间栅格、遥感或洪水分析通过异步任务接入。

GIS 调用统一要求：

- 输入明确 `project_id`、授权图层 ID、空间范围、时间范围和 CRS。
- 输出使用 Artifact 描述，不将大文件放入 LLM 消息。
- Artifact 支持 GeoJSON、COG、GeoPackage、MVT、PNG 和业务统计 JSON。
- 写图层、覆盖、发布和共享必须进入高风险审批。
- 结果保存来源图层版本、算法版本、参数、CRS、包围盒和生成时间。

### 13.3 Web 地图交互

- 对话中的 GIS 结果以“成果图层卡片”展示，可添加到主地图、缩放定位、调整透明度、查看图例和下载。
- 地图页面通过事件总线或嵌入式 Chatbox SDK 接收 `artifact.ready` 事件。
- Agent 获取页面上下文时只接收当前工程、地图范围、选中对象和授权图层标识，不直接信任浏览器提供的业务权限。

## 14. 凭据、审计与可观测性

### 14.1 凭据

- 模型 API Key、MCP Header、外部 Agent Token 统一保存至 Secret Store。
- 管理 API 仅返回凭据名称、引用和最后更新时间，不返回明文。
- 按 Run 生成短期凭据或在服务端代理调用，避免密钥进入沙箱和模型上下文。

### 14.2 审计

审计事件至少覆盖登录、资源增删改、发布、权限变更、知识检索、模型调用、工具调用、审批、控制命令、文件下载和外部 Agent 调用。审计记录追加写入，不与可编辑业务表混存。

当前已实现统一 `audit_events` 追加写模型和 `/api/audit/events` 列表、详情、关联事件接口，覆盖 Agent、tool、LLM 运行事件及 Agent、MCP、Tool、模型供应商等选定管理操作。列表支持类别、来源、操作、状态、风险、项目、用户、关键词和带时区发生时间筛选；时间值必须带 `Z` 或明确偏移。服务端范围固定为 `unit_auditor` 当前单位、`project_admin` 当前项目、普通 `user` 本人事件，筛选参数不能扩大范围；不存在和越权详情统一返回安全 404。

记录器只接受显式允许的元数据字段，并执行递归敏感字段脱敏、HTML 转义、深度和大小限制。审计摘要和元数据不得包含凭据、口令、客户数据或原始 Prompt。当前 API 不提供审计更新或删除操作。

历史 Agent Run 回填由运维人员在 API 启动前或独立维护窗口显式运行 `python -m app.audit.backfill`；命令按批提交，以稳定幂等键写入，可安全重跑，且不会随 API 启动自动执行。执行前必须确认 `DATABASE_URL` 指向目标测试或维护数据库。

知识库真实审计、真实 MCP 工具执行、沙箱审计、审计导出、保留期自动化和跨服务事件总线仍未实现；`source` 枚举和前端筛选项仅为统一契约预留，不代表这些链路已交付。

### 14.3 指标和追踪

- 每个请求、会话、Run、模型调用、工具调用和外部任务贯穿 `trace_id`。
- 统计 Token、模型费用、检索耗时、工具成功率、审批等待、沙箱资源和外部任务耗时。
- Prompt、知识片段和敏感参数按数据等级脱敏，不能默认全部写入日志。

## 16. API 和数据设计原则

- API 路径使用内部 UUID，业务编码作为可修改字段。
- 创建、发布、运行和审批接口支持幂等键。
- 列表统一支持分页、搜索、状态、作用域和更新时间过滤。
- 更新接口使用版本号或 ETag 实现乐观锁，避免多人覆盖配置。
- 删除默认软删除，审计、运行、消息和已发布版本不可物理级联删除。
- 数据库正式环境使用 PostgreSQL；Redis 用于队列、短期状态和取消信号；对象存储保存文档与成果；向量检索可先使用 PostgreSQL pgvector，再按规模拆分。
- SQLite 保留为本地开发和单元测试适配器，不再作为生产架构假设。

## 19. 测试与验收设计

### 19.1 必须新增的自动化测试

- 用户不能读取其他租户的 Agent、Skill、MCP、知识、会话、Run 和成果。
- 相同业务编码可在不同租户存在，内部 ID 不冲突。
- Agent 发布时能拒绝无权访问、已停用或版本不存在的绑定资源。
- Web、Desktop、Common 正确选择不同上下文 Prompt。
- 多个 Skill 按 Agent 固定版本加载，停用或删除不会破坏历史 Run。
- 高风险工具创建审批并中断，低风险只读工具可自动执行。
- 审批后参数变化、过期、越权审批和重复恢复均被拒绝。
- 取消 Run 能终止沙箱和外部异步任务，并保持幂等。
- RAG 检索先过滤权限，答案引用能定位到有效文档版本。
- 失效或未审核知识规则不能驱动行为。
- MCP 密钥不出现在 API、日志、Prompt、检查点和审计明文中。
- stdio MCP 和脚本 Skill 不在 API 主进程执行。
- GIS 请求缺少 CRS、越权图层或非法成果类型时被拒绝。
- GeoLibre 异步任务能够提交、回传、取消和保存 Artifact。

### 19.2 非功能验收

- 运行事件可断线重连，不重复执行已确认工具。
- 单租户限额不会影响其他租户。
- 所有关键调用可通过 `trace_id` 追踪。
- 沙箱在成功、失败、超时和取消后均能清理。
- 后端多实例部署时检查点、审批和取消仍然有效。

## 20. 当前阶段结论

当前项目已经形成 Agent、Skill、MCP 和模型供应商的管理界面与基础 API，并具备 Agent/tool/LLM 与选定管理操作的统一审计基础闭环；但知识库真实审计、真实 MCP 执行、沙箱、导出、保留自动化和事件总线仍未实现，平台尚不是完整的多用户 Agent 运行系统。

最需要优先修改的不是继续增加管理页面，而是建立四个底层闭环：真实身份与租户隔离、不可变 Agent 版本、PlatformAgentHarness 运行链路、风险审批与审计。完成这四项后，再接入 RAG、沙箱和 GeoLibre 等专业智能体，现有管理功能才能真正参与可控、可恢复、可审计的业务执行。
