# 默认智能体与运行时配置设计

## 目标

平台始终提供一个可用的默认智能体，并让智能体管理页面中的模型、提示词、Skill 和人工确认策略成为真实运行配置。当前阶段采用平台全局默认，保持单单位、多项目数据边界，预留后续单位级和项目级默认覆盖能力。

## 方案选择

采用“内置保底智能体 + 可切换平台默认”的方案：系统自动确保内置智能体 `platform-default-agent` 存在且永久不可删除；管理员可以将其他已启用智能体设为当前平台默认。当前默认智能体不可删除或停用，切换后原默认智能体恢复普通管理规则，但内置保底智能体仍不可删除。

不采用固定且不可切换的默认智能体，因为这会限制不同部署环境的业务配置。不在本阶段实现单位级和项目级默认，以避免在权限与项目上下文尚未完整接入运行时前扩大复杂度。

## 数据设计

继续使用 `managed_agents` 保存智能体配置，不复制模型、提示词或 Skill 数据。平台当前默认指针存入现有 `platform_settings` 表：

- `setting_key`: `default_agent`
- `value`: `{ "agent_id": "...", "scope": "platform" }`
- `version`: 用于并发更新控制

智能体响应增加两个只读状态：

- `is_builtin`: 是否为平台内置保底智能体。
- `is_default`: 是否为当前平台默认智能体。

`is_builtin` 第一阶段由稳定 ID `platform-default-agent` 判定，不允许客户端修改。后续若引入更多系统智能体，再迁移为独立持久化字段。`scope` 先固定为 `platform`；后续可扩展为平台、单位、项目三级解析，而不改变 Run 中保存实际 `actor_id` 的契约。

## 初始化与一致性

应用启动或首次访问智能体服务时执行幂等初始化：

1. 不存在 `platform-default-agent` 时，创建内置智能体及工作目录。
2. 不存在有效默认指针时，将其指向内置智能体。
3. 默认指针指向不存在或已停用的智能体时，自动回退内置智能体并记录告警。
4. 内置智能体被历史数据置为停用时，自动恢复启用状态。

内置智能体初始使用平台默认模型，具有通用水利业务助手提示词，不默认绑定高风险 Skill，也不获得 Shell、文件写入或设备控制权限。

## 管理规则

- 内置智能体允许修改名称、描述、运行形态、语言、模型、系统提示词、上下文提示词、人工确认策略和 Skill 绑定。
- 内置智能体永久禁止删除。
- 当前默认智能体必须处于启用状态，禁止停用和删除。
- 只有已启用智能体可设为默认。
- 复制默认或内置智能体时，副本是普通、停用且非默认智能体。
- 置顶与默认相互独立；置顶只控制列表排序。
- 所有保护规则由后端服务强制执行，前端禁用按钮仅用于交互提示。

## API 设计

在现有 `/api/agents` 下增加：

- `GET /api/agents/default`：返回当前有效默认智能体。
- `PUT /api/agents/default`，请求体 `{ "agent_id": "..." }`：原子切换平台默认智能体。

现有列表和详情响应增加 `is_builtin`、`is_default`。删除或停用受保护智能体返回 `409 Conflict` 和稳定错误信息；将不存在或停用的智能体设为默认返回 `404` 或 `422`。切换默认使用 `platform_settings.version` 做乐观并发控制，避免并发管理操作互相覆盖。

## 问答解析

发送消息接口允许未指定智能体：

- 用户明确选择智能体时，校验其存在且启用，并将实际 ID 写入 `AgentRun.actor_id`。
- 未指定智能体时，由后端解析当前平台默认智能体并将其实际 ID 写入 Run。
- 前端不再硬编码 `flood` 作为默认值，而是加载后端默认智能体。

Run 必须保存解析后的实际智能体 ID，而不是保存“default”别名，保证历史审计和默认切换后的结果可复现。团队运行仍沿用当前未支持提示，不在本设计中伪装为单智能体运行。

## 运行时配置

`PlatformAgentHarness` 按 `run.actor_id` 加载智能体配置并验证其启用状态。模型选择规则为：智能体同时配置有效的 `provider_id` 和 `model` 时优先使用该模型，否则回退平台当前启用的默认模型。凭据仍只从服务端 Provider 配置读取，不进入智能体配置、消息、事件或日志。

发送给模型的消息按以下顺序组装：

1. 平台安全约束和实际运行模型身份。
2. 智能体 `system_prompt`。
3. 与 `runtime_form` 匹配的 `context_prompt`。
4. 经服务端验证的页面、项目、知识库或资源上下文。
5. 对话历史。
6. 当前用户消息。

空提示词不生成空消息。平台安全约束优先级高于智能体配置，智能体提示词不能授予未绑定的 Skill、绕过人工确认策略或扩大沙箱权限。`context_prompt` 只解释上下文使用方式，不直接信任前端传入的指令或资源标识。

本阶段让提示词和模型选择实际生效；Skill 的可调用白名单和人工确认策略继续作为后续 Tool Gateway、LangGraph 与 Deep Agents 运行时的强制输入，不能仅依赖模型遵循提示词。

## 前端交互

沿用现有智能体管理页面视觉样式，只补充行为与状态：

- 当前默认智能体显示“平台默认”标识。
- 内置智能体显示“系统内置”标识。
- 非默认且已启用的智能体提供“设为默认”操作。
- 当前默认智能体的停用和删除操作禁用，并显示原因。
- 内置非当前默认智能体仍禁用删除操作。
- 编辑弹窗保留现有模型、Skill、系统提示词、上下文提示词和确认策略设置。

问答页面启动时加载智能体列表及默认智能体。未进行人工选择时跟随平台默认；用户主动选择后，本次会话使用所选智能体。默认切换不追溯修改已有 Run。

## 错误处理与审计

默认智能体解析失败时优先自愈回退内置智能体；只有数据库不可用或内置数据无法创建时才拒绝运行。智能体不存在、已停用、模型配置无效及上游调用失败均转换为安全的 Run 失败事件，不泄漏 API Key、请求头或上游完整响应。

默认切换、受保护删除/停用拒绝和自动回退应进入平台审计日志；若审计模块尚未接入，服务层先保留结构化日志和明确扩展点。

## 测试与验收

- 验证空数据库自动创建内置智能体和默认指针，重复初始化不产生重复数据。
- 验证内置智能体可编辑但不可删除。
- 验证当前默认智能体不可删除、不可停用，且只有已启用智能体可设为默认。
- 验证切换默认后状态正确，复制不会继承默认或内置身份。
- 验证默认指针失效时自动回退内置智能体。
- 验证未指定智能体的问答解析默认 ID，显式选择仍使用选定 ID。
- 验证 Harness 注入系统提示词和上下文提示词，并按规则选择智能体模型或平台默认模型。
- 验证平台安全提示词顺序优先且敏感凭据不会出现在消息和事件中。
- 验证管理页面的默认标识、设为默认、禁用删除/停用及错误提示。
- 运行后端单元与集成测试、前端组件测试和生产构建。

## 后续演进

后续按 `project -> unit -> platform -> builtin` 的顺序解析默认智能体，并结合角色权限限制可见和可选智能体。LangGraph、Deep Agents、多智能体团队、Tool Gateway、知识库和沙箱运行时复用同一智能体解析结果及配置快照，不改变本设计的默认保护规则与 Run 审计语义。
