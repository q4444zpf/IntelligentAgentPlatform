# 通用智能体平台前端

前端使用 Vue 3、TypeScript、Vite 和 Ant Design Vue 实现，并按 Vue Vben Admin 的典型思路组织路由、菜单、权限、布局和业务模块。当前 AI 对话、Agent 管理、MCP、Skill / Tool、大模型配置、平台总览、`/runs` 和 `/system/audit` 已接入对应后端 API；资源库、Prompt、知识库、流程编排、多智能体协同、部分系统管理和沙箱等页面仍包含 Mock 数据或静态原型。

当前仓库原本没有现成 Vue Vben Admin 工程，因此本目录提供可运行的前端应用骨架；各页面是否接入真实 API 以上述实现边界和实际代码为准。

## 运行命令

```bash
npm install
npm run dev
npm run build
npx playwright install chromium
npm run test:layout
```

本地开发身份需要同时设置 `VITE_DEV_UNIT_ID`、`VITE_DEV_PROJECT_ID`、`VITE_DEV_USER_ID` 和 `VITE_DEV_USER_ROLES`；角色变量可使用逗号分隔的 `user`、`project_admin`、`unit_auditor`。这些值仅用于后端显式开启开发身份时的非敏感测试数据，不是生产认证配置。

默认开发地址：

```text
http://localhost:5173
```

## 当前能力

- Vue Router 路由
- 菜单配置
- 权限码 Mock
- Ant Design Vue 企业级 UI
- 部分资源、业务编排、系统管理和沙箱页面使用 Mock 数据或静态展示
- AI 对话、Agent、MCP、Skill / Tool、大模型供应商和平台总览调用后端 API
- 通用管理列表页
- 沙箱执行状态展示
- `/runs` 展示当前项目、当前用户范围内的真实 Agent Run，支持状态、智能体、关键字、日期筛选和服务端分页。
- 运行详情在打开抽屉时按需加载基础信息、有限事件时间线和工具调用安全摘要；三个区域可独立重试，越权或不存在的资源统一显示安全的 404 提示。
- 列表和详情仅由首次进入、用户操作或手动刷新触发请求，不进行自动轮询；手动刷新会清理详情缓存并重新读取当前数据。
- `/system/audit` 展示真实统一审计事件、聚合摘要、服务端分页，以及类别、来源、操作、状态、风险、项目、用户、关键词和发生时间筛选；时间筛选发送带时区的 ISO 8601 边界。
- `/control` 展示当前项目的控制命令、仿真与审批状态、有效期、执行偏差和回滚操作；执行与回滚请求使用幂等键，并按控制权限隐藏高风险操作。

控制命令的 `awaiting_feedback` 表示执行器已返回成功，仍需真实设备反馈后才能判断成功或偏差。双人审批要求两个不同审批人且发起人不能自审；详情展示策略快照、仿真证明、审批记录、执行尝试和反馈时间。网络中断时保留同一操作的幂等键，先刷新详情再重试；不要为绕过 `unknown` 或执行中状态生成新键。跨项目命令返回 404，过期返回 410，界面使用稳定错误 `code` 而非提示文本匹配。

刷新或重新进入控制台后，未完成的操作显示“核对执行结果”或“核对回滚结果”，仅执行权限可见；确认后使用服务器 `recovery_operation.request_key` 重试原操作，不生成新键。成功后的新偏差反馈会重新进入偏差状态并允许回滚，后续阈值内反馈可恢复成功，历史反馈保留。有效期尚未开始的请求返回 409 并保留已批准状态，可在生效后重试。

部署执行器 JSON、HTTPS、秘密变量、健康检查、外部请求响应和迁移处理见 [后端部署契约](../backend/README.md#控制执行器部署契约)。此前控制 API 尚未发布，`team_version_id` 是当前唯一字段；普通 Artifact 和已有 Team API 不受影响。

发布前执行 `npm test`、`npm run build` 和 `npm run test:layout`。布局测试使用真实 Chromium 检查 390px 视口的横向溢出和分区重叠，可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装浏览器路径。PostgreSQL 和真实 Team 控制链路的环境门禁不能由前端模拟 API 测试替代。
- 审计详情和 Trace 时间线按需加载，Agent 事件可跳转到 `/runs` 的对应运行抽屉；不存在与越权统一显示安全 404。后端按角色限制读取范围：单位审计员为当前单位、项目管理员为当前项目、普通用户为本人事件。

## 审计范围演进

`/runs` 保持 Agent 运行专项审计。`/system/audit` 已实现 Agent、tool、LLM 运行事件与选定管理操作的统一查询，并只展示后端已脱敏、追加写入的审计数据；前端不得提交或展示凭据、口令、客户数据或原始 Prompt。

知识库真实审计、真实 MCP 工具执行、沙箱审计、审计导出、保留期自动化和跨服务事件总线仍是后续能力。来源筛选中出现对应枚举不代表这些执行链路已经实现。
