# 阿里云 ECS 公网 HTTP 部署设计

## 目标

将当前工作区中的水利智能体平台部署到阿里云 ECS `39.108.91.166`，通过公网 HTTP 提供 Web 控制台和 API。部署完成后，访问 `/` 可打开前端，访问 `/api/health` 返回 `{"status":"ok"}`，服务器重启后服务自动恢复。

## 部署范围

- 部署当前工作区中的 Vue 3/Vite 前端和 FastAPI 后端。
- 包含当前尚未提交的源代码修改，但不修改或覆盖这些用户改动。
- 排除 `.git`、依赖缓存、开发构建产物、日志和本地 SQLite 数据库。
- 首次部署创建独立的服务器端 SQLite 数据库，不复制本机 `backend/data/model-providers.db`，避免携带本地模型凭据。
- 本次仅使用公网 IP 和 HTTP，不配置域名或 TLS 证书。

## 架构

使用 Docker Compose 管理两个服务：

1. `web`：Nginx 托管 Vite 生产构建产物，对外绑定 TCP 80；将 `/api/` 请求反向代理到内部 `api:8000`。
2. `api`：运行 Uvicorn/FastAPI，仅加入 Compose 内部网络，不向公网映射 8000 端口。

后端数据库文件通过命名卷或宿主机持久化目录挂载，并使用 `MODEL_PROVIDER_DATABASE` 指向挂载路径。容器设置自动重启策略，以便 Docker 或服务器重启后恢复服务。

## 构建与发布

- 前端采用多阶段镜像构建：Node 20 阶段执行 `npm ci` 和 `npm run build`，Nginx 阶段仅保留 `dist`。
- 后端采用 Python 3.12 精简镜像，安装 `backend/requirements.txt`，以非开发模式启动 Uvicorn。
- 使用部署忽略文件阻止本地数据库、缓存、密钥文件和 Git 元数据进入构建上下文。
- 将项目打包上传到服务器的独立发布目录，再由 Docker Compose 构建并启动。

## 网络与安全

- 公网仅需要 SSH 管理端口和 TCP 80；FastAPI 端口不直接暴露。
- 不把服务器密码、模型密钥或其他凭据写入仓库、镜像、Compose 文件或日志。
- 不修改 SSH 登录策略，待部署成功后由用户更换已在聊天中暴露的密码，并建议改用 SSH 密钥。
- 若阿里云安全组未开放 TCP 80，需要在控制台开放；服务器内防火墙只做必要的 HTTP 放行。

## 前端路由与 API

Nginx 对前端路由使用 SPA 回退：静态文件不存在时返回 `index.html`。`/api/` 保持原始路径代理至 FastAPI，因此现有前端相对 API 地址无需改变。Nginx 转发常用代理头，并设置合理的连接与响应超时。

## 数据与回滚

- SQLite 数据独立于应用容器持久化，重新构建镜像不会删除数据。
- 更新前保留上一发布目录和数据库备份。
- 若健康检查或页面验证失败，停止新服务并恢复上一版本；首次部署失败则停止容器，不影响服务器上的其他服务。
- 在执行前检查 80 端口和已有 Docker/Compose 项目，若存在冲突则停止并请求用户决定，不擅自替换现有服务。

## 错误处理

- 本地先运行后端测试和前端生产构建。
- 连接服务器后检查操作系统、架构、磁盘空间、Docker、Compose、80 端口和当前防火墙状态。
- 安装缺失的 Docker 组件前确认使用服务器对应发行版的官方软件源。
- 每个阶段失败即停止后续发布，并保留可诊断日志；不通过忽略错误来强行上线。

## 验证标准

1. 本地后端测试全部通过，前端生产构建成功。
2. `docker compose ps` 显示服务正常运行。
3. 服务器本机请求 `http://127.0.0.1/api/health` 返回 HTTP 200 和 `{"status":"ok"}`。
4. 公网请求 `http://39.108.91.166/api/health` 返回相同结果。
5. 公网访问 `http://39.108.91.166/` 返回前端页面，刷新前端子路由不会出现 404。
6. 重启容器组后服务仍能恢复，SQLite 持久化路径仍存在。

## 非目标

- 本次不配置 HTTPS、域名、CDN、负载均衡、自动扩缩容或 CI/CD。
- 本次不迁移本地模型供应商数据库和密钥。
- 本次不开发新的业务功能，也不重构现有前后端代码。
