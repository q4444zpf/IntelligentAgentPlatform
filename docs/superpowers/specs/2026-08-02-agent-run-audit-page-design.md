# Agent Run 运行审计页面设计

## 1. 背景与目标

当前 `/runs` 路由仍复用多智能体协同占位页面，与“Agent Runs”菜单名称不一致。Web 问答已经将 Agent Run、运行事件和工具调用记录持久化到 PostgreSQL，但管理员无法在页面中按项目查询和审计这些数据。

本阶段交付一个生产 MVP 范围的 Agent Run 专项页面，用于查看 Web 问答产生的运行记录、事件时间线和工具调用审计。页面沿用现有控制台布局和 Ant Design Vue 组件，不调整全局视觉风格。

## 2. 范围

### 2.1 本阶段包含

- Web 问答产生的 Agent Run 分页列表。
- 按状态、智能体、时间范围、会话标题或 Run ID 筛选。
- Run 基础信息、运行事件时间线和工具调用记录详情。
- 项目和用户数据隔离。
- 安全摘要展示、加载错误恢复、空状态和运行中状态。
- 对现有真实 DeepSeek 工具调用 Run 的浏览器验收。

### 2.2 本阶段不包含

- LangGraph 和多智能体工作流运行记录。
- MCP、知识库、沙箱和模型调用的统一审计。
- 实时推送或自动轮询。
- 修改或重放历史 Run。
- 展示 API Key、完整提示词、模型原始响应或未脱敏业务数据。

## 3. 架构边界

`/runs` 保持 Agent 专项运行页面，继续使用现有 `agent_runs`、`run_events` 和 `tool_invocations` 数据模型。后期建设 `/system/audit` 统一审计中心时，新增统一执行记录或聚合查询层，汇总 `agent`、`mcp`、`knowledge`、`sandbox` 和 `llm` 等来源，不把非 Agent 记录强行写入 `agent_runs`。

本次接口保留稳定的分页、状态、时间范围、`actor_type` 和 `actor_id` 字段。后期统一审计中心可以跳转到本页面的 Agent Run 详情，无需重做本页面。

## 4. 后端设计

### 4.1 查询接口

新增：

```http
GET /api/agent-runs
```

查询参数：

- `page`：从 1 开始，默认 1。
- `page_size`：默认 20，最大 100。
- `status`：可选，精确匹配运行状态。
- `actor_id`：可选，精确匹配智能体 ID。
- `query`：可选，匹配 Run ID 或会话标题。
- `started_after`、`started_before`：可选 ISO 8601 时间边界。

响应结构：

```json
{
  "items": [
    {
      "id": "run-id",
      "conversation_id": "conversation-id",
      "conversation_title": "会话标题",
      "trigger_message_id": "message-id",
      "trigger_summary": "触发消息安全摘要",
      "actor_type": "agent",
      "actor_id": "platform-default-agent",
      "status": "completed",
      "tool_invocation_count": 2,
      "duration_ms": 1200,
      "created_at": "2026-08-02T22:38:00+08:00",
      "updated_at": "2026-08-02T22:38:01+08:00"
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "summary": {
    "total": 1,
    "completed": 1,
    "running": 0,
    "failed": 0,
    "tool_invocations": 2
  }
}
```

详情继续复用：

- `GET /api/agent-runs/{run_id}`
- `GET /api/agent-runs/{run_id}/events`
- `GET /api/agent-runs/{run_id}/tool-invocations`

### 4.2 数据访问与隔离

- Repository 使用一次分页查询获得列表数据，通过聚合查询计算工具数量和统计信息，避免逐条查询。
- 查询必须限制在请求上下文允许的项目和用户范围内。
- 排序固定为 `created_at DESC, id DESC`，保证分页稳定。
- `query` 仅匹配 Run ID 和会话标题，不搜索消息全文。
- `trigger_summary` 从触发消息生成长度受限的纯文本摘要，不返回完整消息。
- 不新增数据库表；仅在查询性能证明确有需要时另行增加索引迁移。

## 5. 前端设计

新增 `AgentRunListView.vue`，并将 `/runs` 从 `GenericModuleView` 切换到该页面。

### 5.1 页面结构

- 顶部统计：运行总数、成功、运行中、失败、工具调用数。
- 筛选栏：状态、智能体、时间范围、会话或 Run ID 搜索、刷新。
- 主列表：状态、智能体、会话、触发摘要、工具调用数量、开始时间、总耗时。
- 分页：使用服务端分页，切换筛选条件时回到第一页。
- 详情抽屉：基础信息、运行事件时间线、工具调用记录。

### 5.2 详情懒加载

列表不批量请求事件和工具调用。用户打开详情后，前端并行加载 Run 详情、事件和工具调用；再次打开相同 Run 可以复用当前页面生命周期内的结果，点击刷新时清除缓存。

工具调用仅展示：

- 工具 ID 和版本。
- 状态和耗时。
- 错误码。
- 后端已保存的参数和结果安全摘要。

前端不尝试解密、恢复或补全被省略的数据。

## 6. 状态与错误处理

- 首次加载显示骨架或表格加载状态。
- 无记录显示明确空状态。
- Run 没有工具调用时显示“本次运行未调用工具”。
- 列表加载失败显示错误提示和重试按钮，保留当前筛选条件。
- 详情部分失败时分别显示错误，不影响其他已成功加载的详情区域。
- `queued` 和 `running` 使用进行中状态；用户可手动刷新。
- 未知状态使用中性标签，不导致页面渲染失败。
- 404 表示记录不存在或无权访问，前端统一显示不可访问提示。

## 7. 安全设计

- 所有接口依赖现有请求上下文和权限校验。
- 列表和详情不返回模型凭据、API Key、完整系统提示词或原始模型响应。
- 参数和结果只展示 `tool_invocations` 中已生成的安全摘要。
- 前端以结构化、只读方式渲染摘要，不执行其中的 HTML 或脚本。
- Run ID、会话 ID、用户和项目标识可用于审计，但不提供跨项目搜索。

## 8. 测试与验收

### 8.1 后端自动化测试

- 返回当前项目和用户范围内的分页 Run。
- 按创建时间和 ID 稳定倒序。
- 状态、智能体、时间范围和查询文本筛选正确。
- 统计数据基于当前筛选范围计算。
- 工具调用数量通过聚合获得。
- 其他项目或用户的 Run 不可见。
- 非法分页和时间参数返回 422。

### 8.2 前端自动化测试

- 页面加载并渲染真实 Run 列表和统计。
- 修改筛选条件会重新请求并重置页码。
- 打开详情时才加载事件和工具调用。
- 正确渲染无工具、失败、运行中和未知状态。
- 列表和详情错误支持重试。
- 路由 `/runs` 指向真实页面而非占位模块。

### 8.3 浏览器验收

- 在 Web 问答发送一次要求调用时间和运行上下文工具的消息。
- `/runs` 列表能找到对应 Run，状态为完成。
- 详情显示 `system.get_current_time` 和 `system.get_runtime_context` 两条完成记录。
- 页面展示的耗时和后端工具调用接口一致。
- 页面无控制台错误，布局在当前桌面视口无重叠。

## 9. 后续演进

后期统一审计中心新增独立的数据模型或聚合服务，记录统一的单位、项目、用户、会话、Trace ID 和执行来源，并分别关联 MCP、知识库、沙箱和模型调用明细。`/runs` 继续作为 Agent 专项视图，统一审计页面通过 Run ID 跳转到本页面详情。

## 10. 完成标准

- `/runs` 不再显示多智能体协同占位内容。
- 真实运行记录可分页、筛选和查看详情。
- 工具调用记录可审计且不泄露敏感数据。
- 后端、前端自动化测试通过。
- 真实 DeepSeek 工具调用 Run 完成浏览器验收。
