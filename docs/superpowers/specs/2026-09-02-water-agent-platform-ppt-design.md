# 水利智能体平台建设方案 PPT 设计说明

## 汇报目标

面向水利行业领导，以三页内容说明平台为什么值得建设、建设内容如何形成体系，以及优先在哪些业务场景落地。汇报结束后，领导应形成一个明确判断：平台不是单一聊天工具，而是连接水利数据、知识、模型、工具和多智能体协作的统一智能决策与安全运行底座。

## 输出范围

- 输出一份可编辑的三页 PowerPoint，不另设封面、目录和结束页。
- 三页依次为总体架构、核心功能、应用场景。
- 视觉风格继承《0-南水北调中线工程多水源供水保障与智慧调控技术-中期汇报定稿版.pptx》。
- 内容以仓库现有总体架构设计、功能设计与当前实现说明为依据，不虚构建设成效或量化指标。

## 叙事结构

### 第 1 页：总体架构

**页面结论：** 构建统一、安全、可扩展的水利智能体平台，贯通多端入口、智能体编排、专业能力接入和运行治理。

采用自上而下的五层架构：

1. 多端访问：Web 管理控制台、AI 对话工作台、嵌入式 Chatbox、桌面客户端。
2. 智能应用：单智能体、多智能体团队、可视化工作流、业务专题应用。
3. 能力中心：知识库、Skill、MCP 工具、水利模型、GIS 与外部智能体。
4. 运行底座：任务调度、模型路由、沙箱执行、会话与成果管理。
5. 安全治理：用户与项目权限、风险审批、运行审计、监控与追踪。

数据、模型、知识和业务系统作为平台连接的基础资源贯穿各层。版式优先复用参考稿第 48 页的总体架构表达。

### 第 2 页：核心功能

**页面结论：** 平台围绕“资源管理、智能编排、安全运行”形成完整业务闭环。

六项核心能力：

1. 智能体管理：配置、版本、发布和 Web/Desktop/Common 运行形态。
2. 多智能体协作：团队角色、任务分工、条件分支、并行协同和人工介入。
3. 专业能力管理：水利模型、Skill、MCP、知识库、GIS 和外部服务统一接入。
4. 工作流编排：拖拽式流程设计、节点配置、检查点、暂停恢复和运行追踪。
5. 多端交互与成果：专属会话、上下文、文件、引用、地图成果和通知。
6. 安全运营：多用户权限、工具白名单、风险审批、沙箱、审计和监控。

页面用一条主闭环串联六项能力，避免堆砌产品卡片。版式优先复用参考稿第 46 页或第 16 页的能力体系表达。

### 第 3 页：应用场景

**页面结论：** 平台优先服务高频、高价值、可闭环的水利业务，并为控制类操作保留人工确认。

四类优先场景：

1. 防洪预报与应急会商：汇聚雨水情、预报模型和预案知识，辅助形成风险研判与处置建议。
2. 水资源配置与供水调度：调用配置和调度模型，开展供需分析、方案比选和调度建议生成。
3. 工程运行辅助：面向水库、闸门、泵站和河网开展状态分析、异常诊断与控制方案校核；控制指令必须经过权限校验和人工审批。
4. 工程知识与成果服务：检索规程、报告和历史案例，生成带引用的答复、专题报告和 GIS 成果。

页面统一呈现“感知与提问 → 智能分析 → 方案生成 → 人工确认 → 执行反馈”的业务闭环。版式优先复用参考稿第 63 页，并吸收第 14 页和第 49 页的场景展示方式。
